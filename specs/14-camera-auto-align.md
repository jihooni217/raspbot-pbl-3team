# 지시서 14 · 카메라 자동 맞추기 (출발 전 보정)

## 목표
START에 로봇을 놓고 실행하면, 카메라가 트랙의 노란 차선을 보고 **좌우(팬)·위아래(틸트) 서보를 스스로 조금씩 움직여** 기준 화면과 같은 각도로 맞춘다. 바퀴는 쓰지 않는다.

## 왜
- 로봇을 박스에 넣으려면 카메라를 돌려야 해서, 꺼냈다가 손으로 정면을 맞추면 매번 몇 도씩 틀어진다.
- 13번 주행 값(차선 위치·색 검사 영역·천천히 글자 크기)은 모두 **잘 달린 판의 화면 각도**를 기준으로 정했다. 각도가 틀어지면 같은 코드도 다르게 달린다.

## 기준 화면
- 2026-11-04 잘 달린 판의 블랙박스 영상(카메라 팬 약 80 · 틸트 5, 로봇 `results/videos/blackbox_20261104_204945_297796_6c23c5b9.mp4`, 비교용 `blackbox_20261104_214713_354784_1c79a793.mp4`)을 기준으로 삼는다. 레포에는 영상이 아니라 **기준 숫자만** 적는다 (`results/camera_align/reference.json`).
- 기준 숫자 (Codex가 영상 START 근처 장면에서 재서 적는다):
  - 두 노란 선이 만나는 점(소실점)의 가로 위치 `vx_ref` (가운데 320 근처일 것)
  - 검은 바닥이 끝나는 줄(트랙 위쪽 끝) 높이 `floor_top_ref`, 또는 노란 선이 화면에서 처음 보이는 높이 `lane_top_ref`
  - 화면 맨 아래 줄에서 두 노란 선 사이 폭 `width_ref`
- 1° ≈ 10픽셀 (사진 시험에서 틸트 20° 차이 = 200줄). 실제 값은 맞추면서 재서 기록한다.

## 만드는 것
- `missions/14_camera_align.py`
  - `measure(frame)` → 소실점 x · 바닥 끝 높이 · 아래 폭 · 믿을 만한지(두 선이 다 보이나)
  - `align(bot, camera)` → 재고 → 서보 1°씩 → 0.3초 기다리고 다시 재기, 반복
  - 끝나면 최종 팬·틸트 값을 `results/camera_align/last.json`에 저장하고 화면에 「팬 82 · 틸트 6 · 소실점 오차 4px」처럼 보여 준다
- 13번은 시작할 때 `last.json`이 있으면 그 값으로 카메라를 맞추고, 없으면 팬 80 · 틸트 5로 맞춘다 (13번에 이 한 가지만 추가)
- `--photo 사진경로`: 서보 없이 사진 한 장으로 measure만 해 보는 집 시험용

## 규칙표
| 상황 | 행동 |
|---|---|
| 소실점이 기준보다 오른쪽/왼쪽 | 팬을 1°씩 그쪽으로 (어느 방향이 + 인지는 처음 한 번 1° 움직여 보고 정한다) |
| 바닥 끝이 기준보다 위/아래 | 틸트를 1°씩 |
| 오차가 소실점 ±10px · 높이 ±10줄 안 | 끝 |
| 노란 선이 하나도 안 보이거나 한쪽만 | 움직이지 않고 「차선 안 보임 — START에 차선 가운데로 놓아 주세요」 |
| 20번 움직여도 안 맞음, 또는 팬 70~90 · 틸트 0~15 밖으로 가려 함 | 멈추고 그 상태와 이유를 보여 줌 (손으로 대충 맞춘 뒤 다시) |

## 성공 기준 (숫자로)
- 집 시험(사진): 기준 장면을 가로·세로로 ±10·±20·±30픽셀 옮긴 사진 12장에서 **measure가 고칠 방향을 12/12 맞힘**, 고칠 양 오차 ±1° 안
- 학교 시험(실물, 바퀴 안 씀): 손으로 팬·틸트를 ±5°쯤 틀어 놓고 실행 → **5번 중 5번** 기준 ±1° 안으로 돌아옴, 한 번에 10초 안
- 맞춘 뒤 13번 사진 시험 점수가 기준 각도와 같게 나옴 (각도 때문에 점수가 바뀌지 않음)

## 안전
- 바퀴는 쓰지 않는다. 서보만, 한 번에 1°씩
- 팬 70~90 · 틸트 0~15 밖으로는 절대 보내지 않는다 (박스에 넣을 때 돌리는 큰 각도는 손으로)
- 실행 전 「카메라 앞을 손으로 가리지 말고, 로봇을 START 차선 가운데에 놓았나요? (y/n)」

## 바꿔 볼 값
- 끝내는 오차 ±10px → ±5px 로 줄이면 시간이 얼마나 늘고 점수가 달라지나

## 구현에서 쓰는 측정 기준 (2026-11-05)
- 기준은 주 영상0번 장면(0부터 세기, 첫 번째 화면,0.000초)이다. START 글자가 보이고 바퀴0인 초기 화면이며 노란 조향 덧그림이 없다.
- 높이는 지시서가 허용한 대안인 `lane_top_ref`를 사용한다. 양쪽 fitted line 주변15px 안에 노란 픽셀3개 이상이5행 연속 나타나는 최초 높이의 평균이다. 실제 검은 바닥/벽 경계를 직접 분류한 값은 아니다.
- 화면 아래 y479에서는 두 노란 선이 화면 밖으로 나가므로, `width_ref`는 두 직선을 y479까지 연장한 투영 폭이다. JSON에 연장값임을 표시하고, 실제 화면에서 두 끝을 직접 본 값으로 다루지 않는다. 폭은 점검용이며 서보 제어 오차에는 쓰지 않는다.
- 노란색은 기존07과 같은 HSV H15~40,S80 이상,V100 이상이다. y60~319에서 좌우 경계를 행별로 재고 튀는 점을 제외해 직선을 맞춘다. 위쪽도 포함해 학교에서 약±5° 틀어진 시작 화면을 잴 여유를 둔다. 각 선40행 이상·세로 범위60px 이상, 직선 오차 중앙값5px 이하인 경우만 신뢰한다.
- 사진 시험의 방향은 화면에서 바라봐야 할 방향이다. 소실점이 오른쪽이면 카메라를 오른쪽으로, 노란 선 시작이 아래로 옮겨졌으면 아래로 바라보도록 고친다. 서보의 +/− 부호는 화면 이동의 부호와 구분한다.
- 최초 보정량은1°=10px로 추정한다.2px 이하는 방향 표시 잡음으로 보고, 실제 정렬 종료는 지시서대로 두 오차 모두±10px 안이다. 따라서±10px 사진도 목표점 쪽 방향은 계산하지만 실물 반복문에서는 허용 오차 안이면 움직이지 않을 수 있다.
- 실물 `align`은 시작 각도(last 값, 없으면80/5)가 현재 명령 각도라는 전제로1°씩 움직인다. 실제 현재 각도를 읽는 센서는 없다. 시작 명령 각도가 다르면 학교에서 `--pan`, `--tilt`로 알려 준다. 부호/픽셀 반응을 모르면 첫1° 뒤 화면 반응으로 배운다. 잘못된 JSON/범위 밖 각도는 서보 명령 전에 거절한다.
- 성공할 때만 `last.json`을 저장한다. 집 가짜 장치 검증의 저장 위치는 임시 시험 폴더이며 실제 `last.json`은 만들지 않는다.
- 13번에는 START 준비 확인 후 저장 각도(last 없으면80/5)를 전송하는 기능만 추가한다. 자동 영상 보정은14번에서만 한다. 사진 시험의 import에는 서보·카메라·바퀴 접근이 없다.
